# Cimbarpunk 1.0.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the first GitHub release as `v1.0.0` with verified Windows x64 and Linux x64 binaries, corresponding recursive source, checksums, and no macOS artifact or support claim.

**Architecture:** Keep the release change limited to the four existing version assertions plus this audit plan. Build and verify each platform from the same source content, package the already-verified install trees, then create one release commit on `main`, a `v1.0.0` GitHub tag/release, and read the remote release back for verification.

**Tech Stack:** C++20, Qt 6.8.4 exact, CMake 3.25+, Ninja, CTest, PowerShell 7, Bash, OpenSSH, Git, GitHub CLI.

**Spec:** `AGENTS.md`, `README.md`, `docs/verification/2026-08-23-linux-gui.md`, and the user request to publish 1.0.0 without macOS.

## Global Constraints

- Work directly on `main`; do not create a branch or worktree.
- Preserve all unrelated tracked and untracked user changes.
- Windows uses Qt `6.8.4` from `D:\Softwares\cqp-684\Qt`, vcpkg from `D:\Projects\Cimbarpunk\.deps\vcpkg`, and dynamic FFmpeg `7.1.1#6`.
- `libcimbar` remains fixed at `c509e0bb142bfd20e22583fb96f520e8083f3fba`; its nested samples submodule remains initialized.
- Linux claims are limited to Ubuntu 24.04.4 x64 with Xfce/X11/Xvfb/XCB; Wayland, physical displays, other desktops, XRDP sessions, and macOS remain unverified.
- Release assets must not include test helpers, stale install files, or macOS artifacts.
- Binary distribution must include the verified license tree and a custom corresponding-source archive containing both fixed submodules.
- The current request authorizes the one minimal release commit, push, tag, and GitHub release needed to publish; no other Git history mutation is in scope.
