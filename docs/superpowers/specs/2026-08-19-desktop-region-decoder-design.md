# Cimbarpunk 桌面区域解码客户端设计

- 日期：2026-08-19
- 状态：已在设计评审中确认
- 项目许可证：`GPL-3.0-only`
- 首个里程碑：M1（Windows 可用闭环，Linux 构建与自动测试）

## 1. 背景与目标

Cimbarpunk 是一个常驻系统托盘的桌面应用。它让用户选择单个显示器上的桌面区域，持续捕获该区域中的动态 cimbar 图像，通过 [`libcimbar`](https://github.com/sz3/libcimbar) 重建一个文件，并将结果安全写入用户指定目录。

M1 的成功标准是：在 Windows 本机完成“托盘启动 → 区域选择与调整 → 实时桌面捕获 → cimbar 解码 → 文件安全落盘”的完整闭环。Linux 通过 `whale@192.168.43.201` 完成干净构建和非 GUI 自动测试；当前没有 Linux GUI 会话，因此不把 Linux 真实桌面捕获列为 M1 验收项。macOS 保留平台边界，但不构建、不验证，也不宣称 M1 已支持。

## 2. M1 范围

### 2.1 包含

- 系统托盘常驻，不提供主窗口。
- 托盘菜单提供开始捕获、停止捕获、打开保存目录、更改保存目录和退出。
- 在鼠标所在显示器上显示全屏区域选择层。
- 鼠标拖拽创建选区；创建后可整体移动，并可通过八个控制点调整边缘和角点。
- 选区不得跨越显示器。
- 用户确认后捕获所选显示器并只解码所选区域。
- 每次任务只接收一个文件；首个文件完成后自动停止。
- 保留最近一次有效选区，下一次进入选择模式时可直接复用或调整。
- 使用系统通知和托盘状态反馈任务结果。
- 可诊断但不记录捕获内容的本地日志。

### 2.2 不包含

- 编码功能或编码界面。
- 连续接收多个文件。
- 主窗口、历史记录页或独立设置窗口。
- 开机启动、自动更新、遥测和联网服务。
- Windows、Linux 或 macOS 的专用原生捕获后端。
- Linux GUI 捕获验收和任何 macOS 验收。

## 3. 技术决策

采用 C++20、Qt 6、Qt Quick/QML 和 CMake：

- `QApplication` 负责应用生命周期和系统托盘。
- `QSystemTrayIcon` 与 `QMenu` 实现唯一的常驻入口。
- Qt Quick/QML 仅实现区域选择覆盖层，不创建主窗口。
- `QScreenCapture`、`QMediaCaptureSession` 和 `QVideoSink` 构成 M1 捕获后端。
- C++ 直接链接 `libcimbar`，不引入跨语言 FFI。
- 捕获功能位于可替换接口之后；后续可按实测需要增加 Windows Graphics Capture、XDG Desktop Portal/PipeWire 或 ScreenCaptureKit 后端。

选择该方案是为了优先完成可验证闭环，同时保留平台原生优化能力。首版直接开发三套原生后端会产生当前无法在 Linux GUI 和 macOS 上验证的代码；Rust/Web UI 路线则会增加桌面捕获、覆盖层和 C++ 图像数据之间的桥接成本。

## 4. 架构与组件

依赖保持单向：托盘和覆盖层调用会话层；会话层组合捕获、帧管线、解码和输出；解码与输出组件不知道托盘或 QML 的存在。

### 4.1 `TrayController`

创建托盘图标和动态菜单，显示当前状态，并将用户动作转换为会话命令。空闲时允许开始捕获、更改或打开保存目录和退出；捕获时禁用重复启动和更改目录，提供停止捕获。托盘不可用时，应用显示一次致命错误对话框后退出，因为不存在其他入口。

### 4.2 `SelectionOverlay` 与 `SelectionModel`

`SelectionOverlay` 是位于鼠标所在显示器上的无边框、透明、置顶 QML 窗口。首次使用时等待拖拽；存在可匹配的历史选区时，以该选区作为初始矩形。选区建立后进入调整态：内部拖动用于移动，八个控制点用于缩放，紧凑工具栏位于选区外侧。`Enter` 或工具栏按钮开始捕获，`Esc` 取消。

`SelectionModel` 是可独立测试的 C++ 几何模型，负责最小尺寸、边界约束、移动、八方向缩放以及逻辑坐标和捕获像素坐标之间的转换。运行时保存逻辑矩形；持久化时保存相对于完整屏幕几何矩形的归一化坐标和屏幕标识。优先以制造商、型号和序列号的组合标识屏幕；信息不完整时退化为屏幕名称、几何和 DPR 的组合。下次启动无法精确匹配时不复用旧选区。

物理裁剪矩形不直接假设一个固定 DPI 倍率，而是根据实际捕获帧尺寸与所选屏幕逻辑尺寸分别计算 X/Y 比例，再取整并夹紧到帧边界。这样可以覆盖混合 DPI、平台舍入和捕获后端尺寸差异。

### 4.3 `CaptureSession`

`CaptureSession` 是唯一的任务编排器，并保证同一时刻最多存在一个任务。状态机为：

```text
Idle -> Selecting -> Adjusting -> Capturing -> Completed -> Idle
  ^          |            |             |          |
  |          +--Cancel----+-------------+----------+
  +---------------- Error / Cancelled -------------+
```

`Completed`、`Error` 和 `Cancelled` 是执行清理和通知的瞬时状态，随后回到 `Idle`。输出目录在进入 `Capturing` 时形成不可变快照，任务中途修改全局设置不会改变当前任务。

### 4.4 `ICaptureSource` 与 `QtScreenCaptureSource`

`ICaptureSource` 暴露启动、停止、帧到达、后端状态和错误，不暴露 Qt Multimedia 类型给上层。M1 的 `QtScreenCaptureSource` 捕获一整块 `QScreen`。选区内部保持完全透明；捕获态边框、控制状态标签和交互命中区全部位于裁剪矩形之外，并切换为鼠标穿透，因此不会进入送往解码器的图像。

选区允许覆盖整个显示器。当选区贴近屏幕边缘、没有足够的外侧空间显示状态标签时，捕获态不显示标签；当选区覆盖整个显示器时，捕获态覆盖层完全隐藏，只通过托盘显示状态。该退化规则优先保证任何应用 UI 都不会污染被解码图像。

显示器在捕获期间断开，或其几何、分辨率、方向、DPI 发生变化时，当前任务立即失败并要求重新选择，避免静默捕获错误区域。

### 4.5 `FramePipeline`

`QVideoFrame` 只在有效映射期内读取。管线在回调中完成裁剪和必要的像素格式转换，将结果复制到应用拥有的连续缓冲区，然后解除映射。解码运行在独立工作线程，待处理队列容量固定为 1；解码忙碌时，新帧替换尚未处理的旧帧，避免延迟和内存持续增长。cimbar 的喷泉码允许漏帧和乱序，因此优先处理最新帧符合协议特性。

M1 使用单个解码工作线程，避免 `libcimbar` 全局模式配置和解码状态发生竞争。只有性能测量证明需要时，才在保持有界背压的前提下引入并行解码。

### 4.6 `CimbarDecoderAdapter`

该适配器封装 `libcimbar` 的 OpenCV 图像输入、模式探测、喷泉码状态和完成回调。默认自动探测固定上游版本支持的模式，不向 M1 用户暴露模式设置。适配器提供“未识别、已识别有效帧、活动流进度、文件完成、错误”等领域事件，不把上游类型泄漏给会话层。

同一任务可能短暂观察到多个流，但 M1 只接受首个完成文件。完成后停止捕获并丢弃其余未完成流，从而避免循环播放同一内容时重复保存。

### 4.7 `OutputStore`

默认目录是系统下载目录下的 `Cimbarpunk`。用户通过托盘菜单调用原生目录选择器修改目录，选择结果持久化。

输出遵循以下规则：

1. 任务开始前创建并验证目录可写。
2. 优先使用发送端嵌入的文件名，只保留 basename，并清除路径穿越、平台非法字符和 Windows 保留名。
3. 没有有效文件名时使用 `cimbar-<stream-id>-<timestamp>.bin`。
4. 在目标目录内创建仅由本应用命名的隐藏临时文件，边解压边写入，确保最终重命名发生在同一文件系统。
5. 完整写入、刷新并关闭后选择最终名称；同名时按 `name (1).ext`、`name (2).ext` 递增，绝不覆盖。
6. 使用原子重命名提交结果。写入、刷新或重命名失败时删除临时文件并报告失败。
7. 创建临时文件前，将其绝对路径登记到 `QSettings` 的待清理记录中；提交或正常取消后移除记录。启动时只处理已登记、父目录等于当时输出目录且文件名严格匹配 `.cimbarpunk-<UUID>.part` 的路径，不递归扫描目录，也不删除其他文件。

### 4.8 `SettingsStore` 与日志

使用 `QSettings` 的平台原生后端保存当前输出目录、最近一次归一化选区和屏幕标识。捕获帧、文件内容和解码数据不得写入设置或日志。

日志写入 `QStandardPaths::AppLocalDataLocation` 下的滚动文件：当前日志最大 1 MiB，最多保留 3 个备份。日志记录版本、状态转换、后端错误、帧尺寸、丢帧计数、解码进度和最终结果，不保存截图、帧像素或解码文件内容。M1 不发送遥测。

## 5. 用户流程与数据流

1. 应用启动后只显示托盘图标，状态为“空闲”。
2. 用户选择“开始捕获”；应用定位鼠标所在屏幕并显示选择覆盖层。
3. 用户创建或调整矩形。矩形被夹紧在单个显示器内。
4. 用户按 `Enter` 或点击开始按钮。会话锁定屏幕、物理裁剪矩形和输出目录。
5. 覆盖层变为鼠标穿透的捕获状态；边框和状态标签位于裁剪区外。全屏选区或外侧空间不足时按 4.4 节的规则隐藏覆盖层或标签。
6. 捕获后端产生显示器帧，管线映射、裁剪、转换并以有界队列交给解码线程。
7. 解码器累积喷泉码状态。若能报告进度，覆盖层和托盘显示活动流中的最高进度；不能报告时显示“正在识别”，不伪造百分比。
8. 首个文件完成后先停止新帧，再安全结束工作线程，并由 `OutputStore` 原子提交文件。
9. 覆盖层关闭，选区持久化，会话回到空闲。系统通知显示结果；平台支持通知点击事件时，点击后打开文件所在目录。托盘的“打开保存目录”始终可用。
10. 用户按 `Esc`、选择“停止捕获”或退出时，停止生产新帧，等待当前一次解码调用结束，删除未完成临时文件并回到空闲或退出。

## 6. 错误处理

所有任务失败使用相同收尾顺序：停止捕获、拒绝新帧、等待当前解码调用结束、清理本任务临时文件、恢复托盘状态、保留仍有效的选区，并通过托盘状态和系统通知报告错误。

- 保存目录不存在时尝试创建；创建失败、无写权限或空间不足时不静默回退到其他目录。
- 捕获权限被拒绝或后端不可用时结束任务，提示用户检查系统屏幕录制权限，不自动重复请求。
- 后端报告已启动后连续 5 秒没有任何可用帧，判定捕获失败；单个帧映射或转换失败只丢弃该帧。
- 长时间没有解码进展不是错误，不设置自动超时；用户可主动停止。
- 解码器异常在工作线程边界转换为领域错误，不允许异常终止托盘进程。
- 系统通知不可用时，托盘状态、图标提示和日志仍必须反映结果。
- 用户退出时先完成安全停止和清理，不留下后台进程。

## 7. 构建、依赖与许可证

- C++ 标准：C++20。
- 构建系统：CMake 与 CTest；提供 Windows 和 Linux 的 CMake Presets。
- Qt：最低 Qt 6.8，由系统或官方 Qt SDK 提供，不复制到仓库；Windows 打包阶段使用 Qt 官方部署工具收集运行库。
- `libcimbar`：Git 子模块固定为已验证提交 `c509e0bb142bfd20e22583fb96f520e8083f3fba`。
- C/C++ 第三方包：使用仓库内 vcpkg manifest 和固定 baseline；不使用浮动版本。
- Cimbarpunk 自有源码使用 SPDX 标识 `GPL-3.0-only`，仓库根目录提供 GPLv3 正文。
- `libcimbar` 保持其 MPL-2.0 文件级许可证、版权声明和源码可得性；发行包提供第三方 notices。Qt、OpenCV、zstd、wirehair 等依赖按各自许可证履行分发义务。

Qt 和第三方依赖的具体补丁版本在实施计划执行时锁定到能够同时通过 Windows 和 Linux 验证的版本；最低兼容边界保持 Qt 6.8，不使用未经记录的本机隐式依赖。

## 8. 测试设计

所有自动测试由 CTest 统一运行。

### 8.1 单元测试

- `SelectionModel`：首次拖拽、反向拖拽、移动、八方向调整、最小尺寸、屏幕夹紧、负桌面坐标、归一化持久化和混合 DPI 映射。
- `CaptureSession`：所有合法状态转换、重复启动拒绝、取消、错误收尾、退出和输出目录快照。
- `FramePipeline`：裁剪边界、像素格式转换、帧所有权、容量为 1 的替换策略和安全停止。
- `OutputStore`：文件名清理、默认目录、目录创建、同名避让、原子提交、写入失败和仅清理自有临时文件。
- `SettingsStore`：缺省值、持久化、失效屏幕匹配和损坏设置回退。

### 8.2 组件与集成测试

- 使用伪 `ICaptureSource` 驱动完整会话，不依赖真实桌面。
- 使用固定、预生成的 cimbar 动态帧序列测试 `CimbarDecoderAdapter`，以输出 SHA-256 验证内容。
- 测试序列包含乱序、重复和缺失帧，验证喷泉码恢复及最新帧背压策略。
- 使用临时目录注入重名、无权限和提交失败条件。
- Qt 覆盖层的业务几何由 C++ 模型测试；QML 只做绑定和视觉呈现，避免把关键规则留在难以无头测试的脚本中。

### 8.3 Windows 本机验收

1. 从干净配置完成构建，全部自动测试通过。
2. 应用启动后不显示主窗口，托盘菜单完整且退出后无残留进程。
3. 人工验证拖拽、移动、八方向调整、`Enter`、`Esc`、单屏约束和现有硬件可覆盖的不同 DPI 场景。
4. 使用测试帧播放器显示动态 cimbar，真实选择该窗口区域并完成桌面捕获；输出 SHA-256 与原文件一致。
5. 验证边框、控制点和状态标签没有进入送往解码器的裁剪图像。
6. 验证成功后自动停止、选区复用、同名不覆盖、手动停止清理和通知/托盘状态。

### 8.4 Linux SSH 验收

在 `whale@192.168.43.201` 上从干净构建目录完成配置、编译和全部非 GUI 自动测试。可在无头环境执行的 Qt smoke test 使用 offscreen 平台运行。没有图形会话时，不运行也不宣称通过 `QScreenCapture`、托盘集成和覆盖层人工测试。

### 8.5 macOS

M1 不执行 macOS 构建和测试。代码不得把 Windows/Linux 专用头文件泄漏到公共核心接口，但 macOS 可用性必须等到获得环境并完成独立验收后再声明。

## 9. 验收条件

M1 只有在以下条件全部满足时才完成：

- Windows 和 Linux 均能从文档化依赖完成配置与构建。
- 两个平台的全部适用自动测试通过。
- Windows 真实桌面区域捕获能够从动态 cimbar 序列恢复文件，SHA-256 与输入一致。
- Windows 上选择、调整、移动、取消、停止、成功和错误流程均不会产生主窗口、重复任务或残留进程。
- 成功文件通过临时文件和原子重命名提交，同名文件不被覆盖；失败任务不留下可误认为完整文件的产物。
- Linux GUI 和 macOS 的未验证状态在 README 与发行说明中明确披露。

## 10. 已知风险与后续扩展

- Qt 通用屏幕捕获在高分辨率、高帧率下可能产生额外复制和 CPU 开销。M1 先记录帧率、解码耗时和丢帧计数；只有实测不能满足解码闭环时才增加原生捕获后端。
- Wayland 的屏幕捕获受 XDG Desktop Portal 和 PipeWire 权限流程约束，Qt 支持也可能要求系统选择器。该问题在具备 Linux GUI 会话后单独设计和验收。
- macOS 需要 Screen Recording 权限和 ScreenCaptureKit 验证，留待获得环境后处理。
- 后续编码支持应作为独立里程碑增加编码服务和交互入口；不得把编码逻辑塞入 `CaptureSession` 或 `CimbarDecoderAdapter`。
