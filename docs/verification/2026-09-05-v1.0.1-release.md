# Cimbarpunk 1.0.1 发布验证

## 源码与依赖

- libcimbar 更新至 v0.6.8：`bfb0c8e471820ae493cd3694ea6bed5d5ac06c37`。
- 嵌套 samples 保持 `9bbafc5ea0ad27e2a43ec9eee387dd60714a6c7f`。
- 相对旧 libcimbar 提交，上游仅修改 `web/index.html` 和 `web/main.js`，原生代码、构建文件和许可证没有变化。
- 应用、CMake、vcpkg 清单及版本测试同步为 1.0.1；Qt 6.8.4、Windows FFmpeg 7.1.1#6 和 vcpkg baseline 均保持原固定版本。

## Windows

执行：

```powershell
pwsh -NoProfile -File scripts/verify-windows.ps1 -QtRoot 'D:\Softwares\cqp-684\Qt' -VcpkgRoot 'D:\Projects\Cimbarpunk\.deps\vcpkg'
```

- 完整命令退出码 0；全新配置、应用/测试构建、CTest 18/18 通过，耗时 7.95 秒。
- 安装、windeployqt、依赖闭包和许可证镜像检查通过。
- 包内 FFmpeg 插件真实桌面捕获通过；无主窗口的有界托盘启动通过。
- 托盘进程由验证脚本强制停止，不代表人工验证了“退出”菜单。
- 签名状态为 NotSigned。Windows ZIP 的 255 个文件均与验证后的安装目录逐文件比对一致。
- 首次准备依赖时缓存的 pip.exe 启动器失败；重装同版本 pip 26.2.1 后重新运行上述完整验证成功。

## Linux

- 用户授权使用 GitHub Actions 构建，并豁免本次 Linux GUI 验证。
- 成功运行：[33938490249](https://github.com/whalechoi/Cimbarpunk/actions/runs/33938490249)，构建提交 `69e0d29f3278c4cf7d0def64e34f04c06599a486`。
- Ubuntu 24.04 runner 上运行 `bash scripts/verify-linux.sh`，构建、非 GUI CTest 16/16、安装和部署检查全部成功；CTest 耗时 3.85 秒。
- Qt SDK 的 FFmpeg/XCB/SVG 插件、动态依赖和许可证检查通过，完成的 SDK 已保存到缓存。
- 下载归档的 SHA-256 与 CI 清单一致；核对了 821 个归档条目、ELF 执行权限、必需插件、项目及 libcimbar 许可证和构建提交。
- 此前失败分别来自 runner 缺少完整 Clang 开发包、PulseAudio 开发包和 libltdl 开发包；已补齐。Qt 配置强制 `FEATURE_ffmpeg=ON`，缺少后端条件时提前失败。
- 工作流从 CMake 项目读取版本号；vcpkg 缓存由 ABI 决定是否复用，应用版本变化不会强制丢弃可用缓存。

## 产物与边界

- 最终资产为 Windows ZIP、Linux tar.gz、含两个子模块的完整源码 tar.gz 和 SHA256SUMS.txt；本地集中在 `packages/v1.0.1/`。
- 最终发布提交相对 Linux 构建提交只补充工作流缓存回退与验证文档，不改变应用构建输入。Windows 验证后新增的 Linux SDK/CI 调整也不影响 Windows 应用源码。
- 发布时重新从最终提交和固定子模块创建源码归档；资产上传后比对 GitHub SHA-256，并核对发布标签指向最终提交。
- 本次未进行 Linux GUI、真实桌面捕获、夹具端到端和托盘菜单退出验证；不将旧版本证据移用于新二进制。Wayland、物理显示器、其他 Linux 桌面、XRDP 会话和 macOS 均未验证。
